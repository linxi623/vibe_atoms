# Atoms Demo PRD：笔试交付版

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.2，2026-09-29 |
| 目标 | 交付可在线测试、真实生成应用且数据可持久化的网页 Demo |
| 时间约束 | 收到任务后 48 小时内提交，建议专注开发 6–8 小时 |
| 核心闭环 | 输入需求 → Agent 生成代码 → 交互预览 → 对话修改 |
| 延展能力 | 历史版本对比与恢复 |
| 文档性质 | 开发范围与验收方案，不表示功能已实现 |

## 1. 重新规划结论

这不是完整 SaaS 平台，而是小而完整的 AI 应用构建产品。评审者打开在线地址，输入自己的需求，得到真正由模型生成的代码，在网页中操作生成结果，继续提出修改，并在刷新后找回项目和版本。

**优先保证：** 生成真实性、主流程完整性、持久化可靠性、交互质量及在线部署。原完整平台规划保留在 [长期路线图](PRD-platform-roadmap.md)，不作为本次开发范围。

## 2. 挑战要求映射

| 要求 | Demo 实现 | 验收证据 |
| --- | --- | --- |
| 可运行网页应用 | 部署前端与服务端 API | 新浏览器可访问并操作 |
| 类似 Atoms 的体验 | 项目导航、对话、执行过程、预览与代码视图 | 主流程连续可体验 |
| Agent 驱动代码生成 | 服务端真实调用模型，完成规划、生成与基础检查 | 自定义需求产生对应源码 |
| 可视化展示 | 隔离 iframe 执行生成的 HTML/CSS/JavaScript | 按钮、表单等交互实际响应 |
| 真实交互 | 创建、生成、修改、切换预览、恢复 | 操作改变真实项目状态 |
| 数据持久化 | 服务端数据库保存项目、消息、任务、版本 | 刷新和服务重启后仍可读取 |
| 基本流程 | 自动访客初始化、创建项目、生成、迭代 | 不要求评审者输入模型密钥 |
| 延展能力 | 版本差异和恢复 | 对比两版，恢复后预览一致 |
| 在线链接 | 公开 HTTPS Demo 地址 | 从外部网络实测 |

注册并非挑战的独立硬性要求。默认采用真实访客会话以降低试用门槛，不实现假注册；跨设备账户登录留到后续。

## 3. 演示场景

1. 输入“生成一个待办事项应用，支持新增、完成、删除和分类筛选”。
2. Agent 给出简短计划，生成源码，完成基础检查。
3. 在预览中实际新增事项、切换完成状态和筛选。
4. 追加“增加优先级，并保持原来的新增、删除和筛选功能”。
5. 新版本出现，预览可切换至新版本。
6. 对比源码变化，恢复第一版，确认预览一致。
7. 刷新平台，项目、消息和历史版本仍存在。

另以记账工具、咖啡店网站检查通用性。样例提示只是输入快捷方式，不是预置生成结果。

## 4. 功能范围

### P0：必须完成

| 模块 | 最小范围 |
| --- | --- |
| 初始化 | 服务端签发访客会话，浏览器保留会话凭证 |
| 项目管理 | 创建、列表、进入和重命名 |
| 对话生成 | 自定义文本需求、真实模型调用、增量修改 |
| Agent 流程 | 简短规划、代码生成、基础检查、结果摘要 |
| 执行状态 | 真实阶段、耗时、失败提示和重试 |
| 预览 | 可操作 iframe、桌面/移动视口、刷新 |
| 代码 | 查看实际源码、复制与下载 HTML |
| 持久化 | 访客、项目、消息、任务、版本在服务端保存 |
| 延展能力 | 版本列表、源码差异、恢复历史版本 |
| 在线交付 | 可访问部署、模型服务端配置、限流和错误处理 |

### P1：有余力再做

- 指定版本的只读分享链接，可撤销，默认不公开。
- 运行错误上报及一次自动修复。
- 删除项目、搜索项目和轻量登录。

### 本次不做

附件解析、多人协作、多 Agent 并行、消息队列、任意依赖安装、终端、真实后端应用生成、支付、额度商城、自定义域名及复杂生产部署。不能为了视觉润色推迟持久化和真实模型接入。

## 5. 页面与交互

首屏直接进入工作台，不做独立营销首页。

- 左侧：品牌、新建项目、历史项目。
- 中间：聊天、阶段卡片、输入框和发送。
- 右侧：预览 / 代码切换、桌面 / 移动视口、版本标识。
- 顶部：项目名、任务状态、版本历史。
- 无项目时展示输入区与少量样例提示，右侧为空态。
- 窄屏采用对话、预览分视图，不压缩为三列。

| 状态 | 界面行为 |
| --- | --- |
| 初始化中 | 加载状态，暂不允许提交 |
| 尚未生成 | 预览空态，不用预制页面冒充结果 |
| 正在生成 | 真实阶段，禁止同项目重复写任务 |
| 正在迭代 | 保留旧预览，明确新结果尚未完成 |
| 成功 | 版本卡片出现，预览和源码指向同一版本 |
| 失败 | 保留旧版，显示错误类别与重试入口 |
| 保存失败 | 不显示交付成功，允许重试 |
| 查看历史 | 明确版本编号，不误认为当前版本 |

## 6. 功能需求与验收

### F1. 访客与项目

服务端生成不可猜测的会话凭证，通过安全 Cookie 识别访客。项目归属由服务端决定。

- 同一浏览器刷新后能找回项目；新无痕会话不能读取另一访客项目。
- 修改项目、消息或版本 ID 不能越权。
- 清除 Cookie 后不能自动恢复访客项目，此限制在 README 明示。

### F2. 真实 Agent 生成

采用“规划 → 生成 → 检查”的轻量流程，不引入复杂多 Agent 框架。规划整理页面和关键交互；生成输出完整单文件 HTML，内含 CSS 和 JavaScript；检查代码结构、体积和禁用资源。

- 非样例需求真实调用模型并生成对应源码。
- 增量输入包含本轮需求、当前源码及保留约束。
- 模型不可用时明确报错，不静默替换为固定模板。
- 阶段卡片来自实际执行步骤，不使用定时器模拟进度。
- 基础检查不等于完整测试，不能声称所有功能已验证。

### F3. 交互预览与源码

只支持无第三方依赖、无需构建的单文件前端应用，不在服务端执行任意生成代码。

- iframe 执行实际源码，生成应用的关键动作有效。
- 预览、源码与下载文件属于同一版本。
- 桌面/移动切换只改变视口，不修改代码。
- 生成应用不能读取平台 Cookie、DOM、存储和模型密钥。

### F4. 平台数据持久化

项目、聊天、任务和源码版本写入服务端持久数据库。部署环境无持久磁盘时，不能以临时 SQLite 或浏览器存储替代。

- 刷新、服务重启或重新部署后仍能读到记录。
- 成功响应必须发生在版本保存完成之后。
- 浏览器存储不是项目数据的唯一来源。

生成应用内部业务数据与平台项目数据是两回事：本次强制保证后者；生成的待办应用可仅在当前预览会话中保留事项，不能宣称其业务数据也已持久化。

### F5. 增量修改

每次修改固定基线版本，生成成功后才更新当前版本。

- 两轮修改各自反映用户需求，已有关键交互仍可操作。
- 失败不覆盖最后成功版本。
- 同项目执行期间禁止第二个写任务，不实现排队。
- 重复提交使用幂等键，避免重复任务和版本。

### F6. 版本差异与恢复

成功版本不可变；恢复历史源码生成新的恢复版本并记录来源。

- 至少两版的真实源码可对比。
- 恢复前确认目标，恢复后源码和预览一致。
- 不删除后续历史，不调用模型重新生成近似页面。

### F7. 失败与超时

- 区分模型、格式、存储和网络错误；旧版与聊天保留。
- 模型请求有时限，格式修复最多一次，超限后交由用户重试。
- 重试创建关联的新任务。
- 刷新后重新读取服务端状态；不宣称请求一定在后台继续。
- 首版允许中断请求失败，但陈旧运行状态必须按超时规则转为失败。

## 7. 拟定技术方案

这是实现边界，不是已完成的部署承诺：

```text
浏览器工作台
  ├─ 项目 / 对话 / 版本
  ├─ 源码差异视图
  └─ 隔离 iframe 预览
          │
服务端 API
  ├─ 访客会话与所有权校验
  ├─ 生成编排与状态事件
  ├─ 模型适配接口，密钥仅在服务端
  └─ 持久数据库
```

- 单仓库、单部署入口和熟悉的 Web 栈，避免过早拆分。
- 模型经单一适配层调用；输出固定为结构化计划和单文件源码。
- 状态可通过 SSE 或流式 HTTP 推送，数据库结果是最终事实来源。
- 采用有界请求流程，不引入队列或分布式任务系统。
- 开发第一阶段确认托管平台的请求时限；不支持长请求时选择合适托管或缩短流程，不能只让前端无限等待。

### 最小数据对象

| 对象 | 主要字段 |
| --- | --- |
| Visitor | id、会话凭证摘要、createdAt |
| Project | id、visitorId、name、currentVersionId、timestamps |
| Message | id、projectId、role、content、taskId、createdAt |
| Task | id、projectId、baseVersionId、status、stage、error、idempotencyKey、timestamps |
| Version | id、projectId、sequence、html、summary、taskId、restoredFromId、createdAt |

版本保存、当前指针更新和成功任务状态应在同一事务完成，或采取可检测的补偿规则。

### API 职责

| 接口 | 用途 |
| --- | --- |
| `POST /api/session` | 初始化访客 |
| `GET /api/projects`、`POST /api/projects` | 列表与创建 |
| `GET /api/projects/:id`、`PATCH /api/projects/:id` | 详情与重命名 |
| `POST /api/projects/:id/generate` | 首次生成或迭代 |
| `GET /api/tasks/:id` | 查询持久任务状态 |
| `GET /api/projects/:id/versions/:versionId` | 读取源码 |
| `POST /api/projects/:id/restore` | 创建恢复版本 |

所有私有接口在服务端校验访客归属。写接口校验来源并限制频率。

## 8. 公开 Demo 最低安全边界

- 模型密钥只在服务端环境变量，不能进入源码、响应和日志。
- 访客凭证通过安全 Cookie 保存，服务端存储摘要，不信任客户端自报 ID。
- 限制提示词、输出大小、每会话/IP 频率、全局并发、超时及总预算。
- iframe 只授予所需脚本权限，不同时授予同源权限；禁止顶部导航和弹窗。
- 预览使用 CSP，默认禁外部网络、第三方脚本和表单外发。
- 生成应用不处理敏感数据，不下载任意远程资源，不在服务器执行任意代码。
- 聊天和摘要按文本渲染，避免平台自身 XSS；错误日志脱敏。
- 不能把字符串过滤当作完整沙箱，必须结合浏览器隔离和权限限制。

## 9. 测试与提交验收

### 必测用例

1. 新访客输入非预置需求，成功生成可交互页面。
2. 待办应用实际完成新增、完成、删除及筛选。
3. 第二轮增加优先级，旧动作仍有效。
4. 查看两版差异，恢复后预览对应源码。
5. 刷新及服务重启后，项目、消息和版本仍在。
6. 两个独立访客互相不能读写项目与版本。
7. 模型超时、配置错误和保存失败有明确状态。
8. 重复提交不产生重复成功版本。
9. 失败迭代不覆盖旧版预览。
10. 预览脚本不能读取平台 DOM、Cookie 和存储。
11. 外部网络打开在线地址，完成首次生成和一次迭代。
12. 桌面、移动截图检查无关键操作遮挡。

使用待办工具、记账工具和展示站三个不同任务检查通用性；不以三例成功宣称能生成任意应用。

### 提交清单

- 在线 HTTPS Demo 链接及访问说明。
- 源码仓库或源码包，按笔试提交渠道提供。
- README：本地运行、环境变量、架构、部署、功能和限制。
- 建议 2–3 分钟真实生成与版本恢复录屏。
- 演示提示与操作路径，同时允许评审者自由输入。
- AI 工具使用说明及人工验证内容。
- 已知限制：访客身份、单文件前端、无生成应用真实后端、请求中断策略。
- 提交前确认线上模型额度、数据库及部署有效。

**成功定义：** 评审者无需开发环境和个人模型密钥，通过在线 Demo 输入需求，看到真实生成的可交互应用，提出修改，查看并恢复历史版本，刷新后继续访问自己的项目。

| 模型 API 与服务端密钥 | 无法通过真实生成验收 |
