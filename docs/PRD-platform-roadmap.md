## 1. 参考产品与需求边界

### 1.1 已核实的参考能力

| 能力 | 官方说明摘要 | 来源 |
| --- | --- | --- |
| 自然语言创建 | 通过对话描述目标，可提供截图、文件和设计参考 | S1 |
| 构建闭环 | 创建、预览、修改、测试、发布、验证，再主动更新线上版本 | S2 |
| 项目工作台 | 项目管理、工作空间、桌面/移动预览，区分预览版本与线上版本 | S3 |
| Agent 协作 | 单 Agent 或团队模式，包含计划审批、提问、交接、排队及版本恢复 | S4 |
| 执行可见性 | 对话中展示执行活动、工具操作、版本结果和问题修复入口 | S5 |
| 发布管理 | 发布地址、主动更新、自定义域名、下线与发布前安全检查 | S6 |
| 多种产物 | Web、移动 App、视频及文档类产物；可用性受账户和工作流影响 | S7 |

### 1.2 本产品的取舍

- 借鉴“用户决定目标，AI 执行，用户检查并批准交付”的流程，不复制品牌、角色姓名、文案或视觉资产。
- 首版聚焦 Web 项目，不同时建设移动 App、视频、演示文稿等生成系统。
- 多 Agent 的价值是职责明确、过程可追踪和结果可验证；首版不要求多个模型并行调用。
- 研究、数据分析、增长优化、模板社区、连接器和高级云能力进入后续规划。
- 不将“页面已生成”表述为“业务系统可生产使用”；真实数据、鉴权和支付必须独立验收。

## 2. 产品定位与目标

### 2.1 一句话定位

面向非专业开发者和小型团队，通过自然语言对话生成、迭代、预览和发布 Web 项目，并提供可解释的执行过程及可恢复的项目版本。

### 2.2 用户痛点

| 痛点 | 产品应解决的问题 |
| --- | --- |
| 有业务想法，但不会转成开发需求 | 将自然语言整理为目标、页面、交互及验收清单 |
| 传统外包成本高，反馈周期长 | 让用户在同一项目中连续提出修改并快速检查 |
| AI 输出代码后，用户不知道如何运行 | 自动安装允许的依赖、构建并提供交互预览 |
| 修改后破坏已有功能 | 保留版本、展示变更摘要，支持恢复 |
| 看不懂任务进度与失败原因 | 展示阶段、待办问题、错误分类及恢复动作 |
| 预览正常，但上线不可用 | 显式发布、部署检查和线上验证 |
| 不知道一次任务会花多少资源 | 提供预算、余额、消耗记录及成本上限 |

### 2.3 核心目标

1. 用户无需配置开发环境，即可完成第一个可交互 Web 项目。
2. 用户能通过连续对话完成增量修改，保留明确指定的不变部分。
3. 每次交付都能关联代码快照、构建产物和验证记录。
4. 草稿与线上版本隔离，发布与更新由用户明确触发。
5. 模型、执行环境及部署失败可识别、可重试，不破坏最后可用版本。

### 2.4 首版非目标

- 原生移动 App 构建和应用商店发布。
- 任意语言、任意技术栈及任意依赖的通用云 IDE。
- 多人同时编辑同一份代码。
- 真实支付业务、复杂数据库应用、生产用户登录系统。
- 自动执行营销投放、购买服务、发送真实邮件或其他外部写操作。
- 保证任意自然语言需求都能生成安全、合规、生产级应用。

## 3. 用户与核心场景

| 用户 | 核心场景 | 主要成功标准 |
| --- | --- | --- |
| 创业者 | 将想法转成可展示的产品原型 | 可以演示关键流程并分享体验链接 |
| 产品经理 | 验证仪表盘、表单、后台流程 | 页面齐全、交互真实、修改容易 |
| 中小企业运营 | 制作品牌站、活动页、产品介绍页 | 信息准确、移动端可用、链接可访问 |
| 独立开发者 | 快速搭建前端基础并导出继续开发 | 代码可运行、结构清晰、产物可导出 |
| 企业团队，后续阶段 | 构建带鉴权和数据的内部工具 | 权限、数据隔离和审计可靠 |

**典型首版任务：** 创建一个咖啡店网站，包含菜单、营业时间、位置与联系入口；上传店铺图片；调整移动菜单；测试主要链接；发布到平台托管地址。

**能力边界示例：** 首版可以生成订单后台的交互原型，但不能将本地模拟订单、模拟登录或模拟支付展示为真实业务能力。

## 4. 范围与优先级

P0：首版必须具备；P1：首版稳定后的重点增强；P2：平台扩展能力。

| 模块 | P0 | P1 | P2 |
| --- | --- | --- | --- |
| 账户与空间 | 登录、个人空间、资源配额 | 团队邀请、成员角色 | 企业身份系统、组织策略 |
| 项目管理 | 创建、列表、搜索、重命名、删除 | 复制、模板创建 | 社区发现、公开项目 Remix |
| 对话构建 | 流式响应、附件、澄清、计划确认、增量修改 | 可选协作模式、直接指定角色 | 高级目标执行、多方案比较 |
| Agent 执行 | 产品规划、工程实现、验证三个逻辑阶段 | 架构、研究与分析专职角色 | SEO、广告等专项角色 |
| 执行控制 | 进度、排队、停止、失败重试 | 队列重排、编辑、暂停 | 复杂任务依赖管理 |
| 预览与编辑 | 桌面/移动预览、刷新、错误日志 | 元素选择修改、代码编辑 | 多框架项目支持 |
| 版本与导出 | 版本列表、代码恢复、源码 ZIP 导出 | 差异对比、Git 仓库同步 | 分支与团队审阅 |
| 发布 | 平台子域名、更新、下线、安全门禁 | 自定义域名、受控访问 | 多环境部署 |
| 后端能力 | 仅前端与明确标识的模拟数据 | 数据库、应用鉴权、存储、密钥 | 邮件、AI 接口、支付连接器 |
| 用量与运营 | 内部额度账本、用户消耗视图、后台排障 | 订阅、充值及配额策略 | 企业计费与高级分析 |
| 其他产物 | 无 | 有引用的研究报告 | 移动 App、文档、演示文稿、视频 |

**P0 必须端到端交付：** 登录 → 创建项目 → 澄清与批准计划 → 生成 → 预览 → 修改 → 版本记录 → 发布 → 更新/下线。

## 5. 信息架构与页面

### 5.1 首页与项目中心

- 新建项目输入区：需求、附件、提交动作。
- 最近项目和项目列表：名称、缩略图、更新时间、构建状态、发布状态。
- 搜索、排序和进入项目；无项目、无搜索结果、加载失败分别展示。
- 账户菜单：个人信息、额度、用量和设置。
- P0 不展示不可用的 App、Video、连接器或高级模式入口。

### 5.2 项目工作台

| 区域 | 内容 |
| --- | --- |
| 顶部 | 项目名、任务状态、版本入口、额度、发布入口 |
| 对话区 | 消息、澄清问题、计划审批、执行步骤、版本卡片 |
| 输入区 | 需求输入、附件、发送/排队、停止任务 |
| 预览区 | 应用预览、桌面/移动切换、刷新、新窗口打开 |
| 辅助面板 | 文件树、只读代码、构建日志、错误详情、版本列表 |
| 发布面板 | 子域名、目标版本、扫描结果、部署状态、线上地址 |

桌面优先支持双栏操作；窄屏采用对话、预览、日志分视图，不强行压缩所有面板。首版手机端保证查看、对话和轻量预览，复杂文件查看可限制在桌面端。

### 5.3 设置与后台

- 项目设置：名称、导出、删除、部署信息。
- 用户设置：账户信息、用量、额度和隐私说明。
- 运营后台：用户与项目检索、任务诊断、模型健康、资源使用和审计。
- 后台默认不展示原始用户私密内容；查看敏感信息需要额外授权和审计。

## 6. 核心流程与状态

### 6.1 从需求到首版交付

1. 登录后输入需求，可附参考材料。
2. 服务端创建项目，校验额度、文件和并发限制。
3. Agent 整理目标、页面、主要交互及不支持的部分。
4. 信息不足时提出有限的关键问题；允许用户接受明确列出的默认假设。
5. 展示计划卡片：范围、排除项、预计工作和预算上限。
6. 用户批准后开始实施，拒绝或修改计划不产生代码变更。
7. 在隔离环境执行代码生成、构建与基础验证。
8. 验证通过后产生版本卡片及可访问预览；失败则展示报告。
9. 用户体验关键流程，并发起下一轮修改或进入发布。

### 6.2 增量修改

每个修改任务固定输入基线版本。Agent 提取本轮变更和必须保留的约束，变更、构建及验证完成后才提交新的可用版本。构建失败时保留工作检查点，但不将其标记为可发布版本。

### 6.3 状态模型

| 对象 | 状态 |
| --- | --- |
| 任务 | queued → clarifying / awaiting_approval → running → validating → succeeded / failed / cancelled |
| 版本 | checkpoint、building、ready、failed |
| 部署 | unpublished、deploying、live、updating、failed、unpublishing |

- 澄清与审批结束后进入执行；任务终态不可再改写，重试创建关联的新任务。
- 实际阶段允许由服务端状态机校验转换，不由客户端或模型输出直接决定。
- 一个项目只允许一个代码写任务；只读分析任务后续可独立并行。
- 同一项目不能同时进行写任务、版本恢复和发布，避免发布半成品。
- 页面刷新不终止服务端任务；重连时补发事件，恢复真实状态。
- 更新部署失败时，最后一次成功的线上版本继续服务。
- 停止请求先显示“正在停止”，执行器确认停止后才进入 cancelled。
- 停止后保留已完成检查点，但未验证的变更不得冒充成功交付。
- 代码版本、线上部署和业务数据库是独立对象，不能用一个“恢复”动作隐式覆盖。

## 7. P0 功能需求与验收

### FR-01 账户与个人空间

**需求：** 首版采用一种可靠登录方式，例如邮箱验证码；首次登录创建个人空间。平台用户账户与未来生成应用的终端用户账户分离。

**验收：**
- 未登录不能读写私有项目或附件。
- 更换项目 ID、文件 ID、任务 ID 或版本 ID，不能访问其他用户资源。
- 会话过期后要求重新登录，服务端已有任务按既定策略继续运行。
- 登录接口具备请求限流及重复验证码防护。

### FR-02 项目生命周期

**需求：** 支持创建、搜索、打开、重命名、删除及最近项目。保存原始需求、附件引用、消息、任务、版本及部署状态。

**验收：**
- 重复提交同一创建请求只生成一个项目。
- 刷新或重新登录后仍可打开历史项目。
- 删除需二次确认，明确提示线上网站也将下线。
- 删除顺序为停止任务、下线部署、回收资源；失败项可补偿重试。
- 草案建议软删除保留 7 天，之后清理；该期限须在隐私政策和成本评审中确认。

### FR-03 对话、附件与上下文

**需求：** 支持流式消息、消息复制、文本反馈、附件上传及历史加载。P0 附件建议支持 PNG、JPEG、WebP、TXT、Markdown、PDF；文件正文解析与图片识别失败必须显式提示。

**验收：**
- 附件上传完成且通过检查后才能提交引用，不发送半成品文件。
- 每条消息记录附件状态；“收到文件”和“已解析内容”严格区分。
- 默认建议单文件不超过 10 MB、单条消息不超过 5 个文件，限制可配置。
- 不支持的类型、超限、恶意文件和无法解析的 PDF 有具体错误提示。
- 项目持续保存已确认目标与约束；上下文压缩不静默删除关键约束。
- 不自动抓取用户填写的任意 URL；远程读取能力上线前需配置 SSRF 防护。

### FR-04 澄清与计划确认

**需求：** 对缺失的关键需求进行澄清，输出结构化计划；用户可以批准、拒绝或修改。纯问答不应被误判为代码修改。

**验收：**
- 首轮澄清建议最多 3 个关键问题，避免非关键问题阻断构建。
- 计划必须写明页面、核心动作、模拟能力、排除项和验收清单。
- 审批针对具体计划版本，修改后的计划重新审批。
- 仅批准与计划匹配的实施任务；重复批准不会重复执行。

### FR-05 AI 构建与逻辑角色

**需求：** 首版提供规划、实现和验证三个逻辑阶段，可使用同一模型串行执行。默认采用固定前端技术栈、标准模板及依赖许可策略。

**验收：**
- 阶段输出可追踪；实现任务必须产生代码或明确说明没有改动。
- 至少完成依赖检查、构建、页面加载与计划中关键流程的检查。
- 自动修复次数建议最多 2 次，超限后停止并展示原因和下一步。
- 超出前端能力的请求提供可交付替代方案，不创建伪装成真实服务的交互。
- 模型不可用时明确失败；切换模型必须记录实际调用与消耗。

### FR-06 执行过程、排队与停止

**需求：** 展示阶段、耗时、脱敏工具摘要和任务结果；执行中新增需求进入队列，支持移除。停止需确认。

**验收：**
- 显示业务步骤与操作摘要，不展示模型私有推理链、系统提示或密钥。
- 服务端决定状态和事件顺序；断线重连不重复消息或工具卡片。
- 队列按确定顺序执行，前一任务结束后使用最新成功版本作为基线。
- 任务失败或取消后默认暂停队列，用户确认后继续。
- 停止后不再启动新工具调用，终止运行进程并结算实际用量。

### FR-07 交互预览与错误修复

**需求：** 构建成功后提供交互预览，支持桌面/移动视口、刷新和独立窗口。展示运行错误，并可发起一次修复任务。

**验收：**
- 预览标注版本号，能确认当前看的是哪个版本。
- 预览失效、启动中、构建失败和运行异常具有不同状态。
- 支持至少 1440px 和 390px 两种目标视口检查。
- 错误报告包括时间、错误类别、关联版本和脱敏日志。
- 重复点击修复只触发一个任务；修复继续遵守排队、额度与版本规则。
- 用户代码不得读取平台登录 Cookie、平台管理 API 或其他项目数据。

### FR-08 版本与导出

**需求：** 每次成功构建生成不可变版本，记录基线、摘要、创建任务和验证结果。支持恢复历史代码版本及导出源码 ZIP。

**验收：**
- 版本可关联源码、资源引用、构建产物及运行配置版本。
- 恢复前确认目标版本和影响，恢复生成新版本，不删除后续历史。
- 恢复草稿不自动修改线上部署，需用户再次批准更新。
- 导出含源码、许可允许的资源、依赖锁文件和运行说明。
- 导出排除平台凭证、内部日志、其他用户资源及私密执行文件。
- 大文件和二进制资源通过引用或快照保留，不能导出悬空链接。

### FR-09 发布、更新与下线

**需求：** 将指定 ready 版本发布到平台子域名；保留稳定地址；修改草稿不自动上线。支持更新和下线。

**验收：**
- 只有项目所有者可发布，服务端再次校验权限。
- 地址名称采用可配置格式规则，并防止保留词和重复占用。
- 发布前检查版本、资源、构建、扫描及任务空闲状态。
- 高风险密钥泄露、恶意脚本或越权问题阻断发布；P0 不提供高风险绕过按钮。
- 发布基于选定的不可变产物，不直接部署正在变化的工作目录。
- 新部署检查通过后才切换流量；失败保留旧版与错误记录。
- 发布完成展示线上地址和部署版本，提醒验证关键路径。
- 首版仅支持公开站点，发布前告知“任何获得链接的人均可访问”；私有项目编辑权限不等于线上站点私有。
- 下线需确认，地址返回明确的不可用页面，不再暴露旧产物。

### FR-10 用量与额度

**需求：** 即使首版未接入收款，也要限制计算资源并记录消耗。展示余额、任务预算上限、实际用量及失败原因。

**验收：**
- 提交前校验并预留额度，多项目并发不能超额透支。
- 任务结束释放未消耗预留，记录实际消耗，不因重试事件重复扣减。
- 模型调用、构建与部署消耗分开记录；折算规则由产品定价另行确定。
- 平台自身故障和用户取消的结算规则明确披露，前者建议自动补偿。
- 达到成本、Token、工具次数或运行时长上限时终止并保存检查点。
- 长任务在安全边界停止，不因断开浏览器而解除成本限制。

### FR-11 反馈与基础运营

**需求：** 用户可提交反馈和问题截图；系统关联项目、任务、版本和错误 ID。

**验收：**
- 错误提示提供可追踪 ID，不直接暴露内部堆栈和凭证。
- 运营能定位问题，但不能未经授权修改项目或查看私密附件。
- 项目删除、额度调整、部署操作和敏感排障均记录审计。

## 8. P1/P2 增强需求

| 功能 | 核心要求 | 上线门槛 |
| --- | --- | --- |
| 多 Agent 团队模式 | 角色选择、职责分工、依赖顺序、交接与结果汇总 | 解决写冲突、预算叠加和责任归属 |

| 模板与 Remix | 官方模板、公开项目复制 | 作者授权、许可标识、资源及密钥脱敏 |

| 增长工具 | 基础访问指标，后续 SEO 与广告建议 | 统计口径、隐私同意；真实投放单独授权 |
| 其他产物 | 移动 App、文档、演示文稿、视频 | 独立工具链、预览、费用及验收体系 |

**重要规则：** 数据库恢复、代码恢复和线上回滚分别操作。后续支持数据库迁移时必须先评估破坏性、备份数据并由用户确认，不默认同步恢复生产数据。

## 9. 权限与安全

### 9.1 权限矩阵

P0 只有所有者；编辑者和查看者在 P1 开放。

| 操作 | 所有者 | 编辑者，P1 | 查看者，P1 |
| --- | --- | --- | --- |
| 查看聊天与预览 | 是 | 是 | 是，按分享范围 |
| 提交任务、修改代码 | 是 | 是 | 否 |
| 恢复草稿版本 | 是 | 是 | 否 |
| 发布、更新、下线 | 是 | 默认否，可单独授权 | 否 |
| 管理密钥和生产连接器 | 是 | 默认否，可单独授权 | 否 |
| 管理成员、删除、调整账务 | 是 | 否 | 否 |

### 9.2 必须满足的安全要求

- 所有 API 在服务端校验资源所属空间及操作权限。
- 每个项目使用隔离执行环境，限制 CPU、内存、磁盘、时长和并发。
- 生成代码在独立预览域名运行，平台凭证与应用凭证隔离。
- 执行器禁止访问宿主文件、云元数据、内网敏感地址和其他租户资源。
- 外网访问实施域名及协议策略，重定向和 DNS 解析同样校验。
- 外部网页和附件内容视为不可信资料，不能通过提示注入扩大工具权限。
- 文件做类型、大小、恶意内容检查；日志和导出统一脱敏。
- 默认不使用用户项目训练模型；实际供应商数据政策在上线前确认并披露。
- 提供资源删除策略、数据保留期限和供应商清单；适用法规按实际运营地区另行评审。
- 安全扫描通过不等于不存在风险，不宣传自动生成结果为绝对安全。

## 11. 非功能需求

以下为拟定验收目标，不是参考产品实测表现。统计范围应固定模型、模板、区域、负载及任务类型。

| 类别 | 拟定要求 |
| --- | --- |
| 请求响应 | 已登录情况下，提交确认 P95 ≤ 2 秒，显示任务 ID，不包含完整生成时间 |
| 首条状态 | 模型首 Token 不作绝对承诺；5 秒内显示真实排队或执行状态 |
| 首版生成 | 标准前端任务集中，80% 在 5 分钟内完成可用预览 |
| 停止处理 | 确认后 10 秒内停止启动新动作，运行进程按超时策略终止 |
| 平台可用性 | 公测目标按月 99.5%，模型供应商及生成站点单独统计 |
| 可恢复性 | 浏览器断线或执行器重启后可恢复任务记录及最后成功版本 |

| 观测 | 项目、任务、模型调用、构建和部署全链路可关联 |
| 成本 | 任务级硬预算、用户级并发、空间级额度和异常消耗告警 |

## 12. 指标与埋点

### 12.1 北极星指标

**周有效发布项目数：** 一周内由用户确认发布或更新，且部署后健康检查通过的去重项目数。另行观察真实访问和用户反馈，不把“部署成功”直接等同于业务成功。

### 12.2 核心漏斗

注册成功 → 首次创建 → 计划批准 → 首次可用预览 → 至少一次修改 → 首次发布 → 线上验证 → 7 日回访。

| 指标 | 定义 |
| --- | --- |
| 激活率 | 注册后 24 小时内获得首个 ready 版本的用户占比 |
| 构建成功率 | 进入实施的任务中，产生 ready 版本的任务占比；取消单列 |
| 关键流程通过率 | 基准任务集中，通过预定义端到端验收的项目占比 |
| 发布转化率 | 已获得可用预览的项目中，在 7 日内首次发布的占比 |
| 迭代成功率 | 增量任务满足新需求且未破坏指定保留项的占比 |
| 每成功交付成本 | 全部相关模型、执行和存储成本 / 成功交付数，含失败尝试 |
| 用户留存 | 首次激活用户在第 7 天再次创建或修改项目的比例 |

建议事件：`project_created`、`clarification_submitted`、`plan_approved`、`task_started`、`task_stopped`、`build_failed`、`version_ready`、`preview_opened`、`fix_requested`、`publish_succeeded`、`publish_failed`、`version_restored`、`source_exported`。

埋点不得默认记录原始提示词、源码、附件内容或密钥。首版先获得基线，再制定转化与留存目标。

## 13. 异常与恢复

| 异常 | 用户反馈 | 系统处理 |
| --- | --- | --- |
| 模型限流或超时 | 原因类别、重试入口 | 有界退避，禁止无限重试 |
| 额度不足 | 当前余额、预算缺口 | 不启动新任务，保留已有结果 |
| 附件无法解析 | 标记未解析及原因 | 不声称已阅读，可移除或替换 |
| 构建失败 | 错误摘要、修复入口 | 保留最后可用版本，限制自动修复次数 |
| 预览运行错误 | 版本、错误信息、修复入口 | 关联日志，修复任务去重 |
| 用户停止 | 正在停止、已停止及检查点 | 终止工具、释放预留、暂停队列 |
| 浏览器关闭 | 重开后显示实际进度 | 不因客户端离线丢失任务 |
| 执行器失联 | 恢复中或失败 | 租约超时回收，幂等恢复，避免重复写入 |
| 发布失败 | 诊断 ID、重试入口 | 旧线上版本继续服务 |
| 发布扫描未完成 | 扫描中，暂不可发布 | 完成后恢复发布入口 |
| 项目空间满 | 占用与清理建议 | 拒绝超限写入，不删除已有文件 |
| 恶意内容或越权请求 | 拒绝并说明允许范围 | 不执行，必要时审计与人工处理 |

## 14. 交付阶段

阶段按验收门槛推进，暂不承诺固定周数。工期取决于团队、模型、沙箱与部署基础设施的现成能力。

| 阶段 | 交付范围 | 出口条件 |
| --- | --- | --- |
| M0 技术验证 | 单项目生成、隔离执行、前端构建、预览 | 用完整小项目验证代码到预览链路、资源隔离和实际成本 |
| M1 内测 MVP | 全部 P0、任务账本、版本、发布与排障 | 核心流程可用，权限测试与故障恢复通过 |
| M2 商业化 | 订阅、充值、自定义域名、体验优化 | 对账、计费、支持和安全运营闭环 |
| M3 应用能力 | 数据库、应用鉴权、存储、连接器、协作 | 生产数据隔离、迁移、授权与恢复独立验收 |
| M4 平台扩展 | 研究、分析、社区、增长与多产物 | 分模块验证使用率、成本和维护能力 |

建议职责：产品负责范围与验收；设计负责工作台及状态；前端负责平台交互；后端负责账户、任务、版本和账本；AI 工程负责编排、工具和评测；基础设施负责执行隔离与部署；测试负责端到端、安全与异常场景。具体人数待资源评审。

## 15. MVP 发布验收

1. 从空账户完成创建、批准、生成、预览、修改、发布和下线。
2. 使用至少 20 个预定义前端任务覆盖展示站、表单、仪表盘、列表与移动菜单。
3. 建议至少 80% 的基准任务在一次有界自动修复流程内完成关键路径；人工复核质量与模拟能力标识。
4. 指定“不修改”的页面和交互在增量任务中保持可用。
5. 刷新、断网、重连和重复提交不导致任务丢失或重复扣额。
6. 停止执行、模型超时、额度耗尽和执行器异常都有可验证恢复结果。
7. 版本恢复不删除历史，不静默覆盖线上版本。
8. 更新失败保留旧线上站点，发布目标版本与实际线上版本一致。
9. 跨用户项目、附件、任务、版本和导出权限测试全部通过。
10. 预览沙箱、上传扫描、密钥扫描及执行网络边界检查通过，无未处理的高风险缺陷。
11. 源码导出可在干净环境按运行说明启动，不携带平台秘密。
12. 用户可查任务消耗；账本完成重复事件、并发预留和失败补偿测试。
13. 关键平台页面在桌面和移动目标尺寸无阻断操作的溢出或遮挡。
14. 日志、指标、反馈和审计可支持值班人员定位生成与发布故障。

## 16. 风险、假设与待决策

### 16.1 主要风险

| 风险 | 应对 |
| --- | --- |
| 大范围需求导致不稳定生成 | 固定首版技术栈、任务规模限制、模板和基准评测 |
| 多 Agent 成本增加但质量无提升 | 先逻辑分阶段，验证收益后再引入并行角色 |
| 用户将原型当真实业务系统 | 计划、预览和发布前明确提示模拟能力 |
| 增量修改破坏既有结果 | 固定基线、结构化保留约束、回归验证和版本恢复 |
| 沙箱逃逸或滥用部署 | 权限隔离、网络限制、配额、安全扫描及滥用响应 |
| 预览与线上差异 | 同一产物部署、环境区分、部署后检查 |
| 计费争议与无限任务 | 明确预算、硬上限、可追踪账本和补偿规则 |
| 供应商故障或政策变化 | 模型适配层、调用记录、降级及数据政策评审 |
| 产物版权和模板授权问题 | 独立品牌、许可检查、素材来源记录和导出约束 |

### 16.2 当前默认假设

- 首版面向个人使用和小规模内测，个人空间优先。
- 平台界面以中文为主，生成项目可以按提示使用不同语言。
- 平台为自有 SaaS，提供统一托管；暂不提供用户自托管平台。
- 生成项目采用固定前端栈；可交互原型与静态展示项目优先。
- 首版平台密钥由服务端管理，不要求用户提交自己的模型密钥。
- 首版仅公开发布网站；项目编辑内容默认私有，不自动进入公开社区。

### 16.3 需要业务方确认

| 决策项 | 默认建议 | 影响 |
| --- | --- | --- |
| 首批用户与核心场景 | 创业原型、展示站与产品验证 | 模板、默认提示和质量基准 |
| MVP 是否必须含真实后端 | 暂不包含 | 若包含需扩大鉴权、数据和生产运维范围 |
| 部署与数据地区 | 根据目标市场确定 | 模型可用性、延迟、数据政策与合规 |
| 首版商业模式 | 邀请内测 + 配额 | 收款、套餐、对账和客户支持 |
| 模型及供应商 | 实测成本与质量后选择 | 推理成本、生成时长与失败率 |
| 正式名称和品牌 | 独立于 Atoms 的品牌 | 商标、域名与视觉设计 |
| 团队、预算与上线时间 | 技术验证后估算 | M1 范围、资源安排和里程碑 |
| 数据保留、退款与补偿政策 | 上线前明确 | 用户信任、隐私与运营成本 |
